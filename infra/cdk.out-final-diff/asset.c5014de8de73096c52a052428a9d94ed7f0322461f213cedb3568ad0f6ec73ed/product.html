The secure execution harness

What happens after a customer presses send.

Every step has a clear responsibility. The model can request work, but it never receives business credentials or unrestricted system access.

  1. Resolve

    Resolve the business

    The request’s scoped key resolves to tenant context on the backend. The browser never supplies or receives the tenant ID.

  2. Understand

    Understand the request

    The agent keeps the conversation context and determines whether the customer needs an answer, live information, or an action.

  3. Ground

    Retrieve approved knowledge

    Business-specific facts come from tenant-scoped knowledge. Untrusted retrieved text remains reference data, never system instructions.

  4. Gate

    Select an allowed tool

    When current data or an action is required, the runtime exposes only the typed tools enabled for that business.

  5. Validate

    Validate and execute

    The controlled execution layer checks the input and permissions, then calls the business system server-side with scoped credentials.

  6. Filter

    Filter the result

    Only explicitly public-safe fields can enter the customer response. Internal notes, credentials, and private commercial fields stay out.

  7. Respond

    Respond and log

    The customer gets the useful result in the same thread while the decision, tool call, latency, and outcome are written to Logs.
